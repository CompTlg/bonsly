# Thesis notes: sources, third-party material and tools

This file collects everything that has to be mentioned in the thesis: which literature the
implementation follows, which data and code come from somewhere else, which tools were used to make
reference data, and where AI assistance was used. Add an entry here whenever one of these changes,
so the thesis text can be written from this list.

## 1. Base framework

- Lightwave, the teaching renderer of the Computer Graphics group (Saarland University), is the
  base of this renderer (`include/lightwave`, scene format, test harness, BSDF/shape/camera interfaces).

## 2. Literature the implementation follows

| Topic | Source | Where in the repo |
|---|---|---|
| Stochastic progressive photon mapping (SPPM) | M. Pharr, W. Jakob, G. Humphreys, *Physically Based Rendering: From Theory to Implementation*, 3rd ed., 2016, section 16.2. The method itself: T. Hachisuka, H. W. Jensen, "Stochastic Progressive Photon Mapping", ACM Trans. Graph. (SIGGRAPH Asia) 2009. | `src/integrators/sppm.cpp` |
| RGB to spectrum upsampling | W. Jakob, J. Hanika, "A Low-Dimensional Function Space for Efficient Spectral Upsampling", Computer Graphics Forum (Eurographics) 38(2), 2019. | `src/spectral/uplifting.cpp` |
| Emission (illuminant) spectra from RGB, grey special case | Pharr, Jakob, Humphreys, *Physically Based Rendering*, 4th ed., 2023, chapters 4 and 5 (the same design: scale by twice the largest component, multiply by the illuminant). | `src/spectral/uplifting.cpp` |
| Hero wavelength spectral sampling (planned) | A. Wilkie, S. Nawaz, M. Droske, A. Weidlich, J. Hanika, "Hero Wavelength Spectral Sampling", Computer Graphics Forum (EGSR) 33(4), 2014; and the 4th edition of the pbrt book, chapters 4 and 5. | not implemented yet |

The deviations from the book (for example the extra surface test and surface-area correction in the SPPM
photon gather, which are not in pbrt) are described in `HANDOFF.md`.

## 3. Third-party data and code

| File | Origin | Notes |
|---|---|---|
| `data/spectral/srgb.coeff` | Supplementary material of Jakob and Hanika (2019), `tables/srgb.coeff`, copied unchanged. | Coefficient table for sRGB, 64^3 entries. The supplement has no licence file, so it is credited by citation. `src/spectral/uplifting.cpp` contains an own loader and lookup (the supplement's `rgb2spec.c` was read as the specification of the file format and the lookup, but not used, because it relies on x86 SIMD headers). |
| `src/spectral/tools/cie_tables.hpp` | CIE 1931 2-degree colour matching functions and CIE D65 at 1 nm, taken from Mitsuba 3 (BSD licence), which uses the official CIE tables. | Generated by `src/spectral/tools/oracle.py tables`. |
| `unittests/spectral/golden_data.hpp` | Reference values computed with Mitsuba 3.9 (`scalar_spectral` variant). | Generated by `oracle.py golden`. Used only by the unit tests. |

## 4. Tools used to create reference data

- Mitsuba 3 (W. Jakob et al.) was used to render the reference images of the SPPM tests
  (`tests/**/*_ref.exr`, scenes in `tests/sppm/tools/*_reference.xml`) and as the oracle for the
  spectral unit tests (CIE tables, sRGB conversion, spectra).
- The unit tests compare against the reference values; they do not compare against Mitsuba's
  spectra directly, because different spectra can give the same colour (metamerism). The round
  trip colour -> spectrum -> colour is what is tested.

## 5. Use of AI assistance (Claude, Anthropic)

Claude (Claude Code) was used as follows. Everything was reviewed, built and run by the author.

- **Tests and test scenes:** the SPPM regression tests and their scenes (`tests/sppm/**`, including the
  seam tests and the scripts in `tests/sppm/tools`), and the spectral unit tests
  (`unittests/spectral/upsampling.cpp`, the data generator `oracle.py`). The tests were checked by
  confirming that a correct implementation passes them and that deliberately broken implementations
  fail them.
- **Scene generation:** test and demonstration scene files.
- **SPPM:** the integrator was implemented following the pbrt book (section 16.2). Claude helped
  analyse the colour and dark-line artefacts at surface edges and wrote the fix in the photon gather
  (geometric same-surface test and surface-area fraction in `src/integrators/sppm.cpp`).
- **Spectral upsampling:** the table loader and lookup in `src/spectral/uplifting.cpp` were written by
  Claude from the paper's supplementary material. The author implemented the CIE tables and the
  colour conversion (`src/spectral/spectrum.cpp`).
- **Documentation:** `HANDOFF.md` and other explanatory notes were written with Claude.

Suggested wording for the thesis (adapt to the declaration form of the university):

> The SPPM integrator follows section 16.2 of Physically Based Rendering (3rd ed.). The spectral
> upsampling uses the coefficient table from the supplementary material of Jakob and Hanika (2019).
> Claude (Anthropic) was used to write the tests, the test scenes and the table lookup, and to help
> find and fix artefacts in the photon gather. All code was reviewed and tested by me.
